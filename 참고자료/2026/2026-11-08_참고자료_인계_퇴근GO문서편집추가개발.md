# [인계] 2026-11-08 퇴근GO 문서편집 추가 개발 완료

- 작성: 2026-11-08 / 작성 환경: 노트북 클로드 코드 (퇴근GO 저장소 `바탕화면\정책보고서1`)
- 관련 업무: 퇴근GO 국회 질의 답변자료 서식 — 회사 PC 인계 「[인계] 2026-11-08 퇴근GO 문서편집 추가 개발」의 후속
- 이어서 할 곳: 회사 PC 또는 노트북 (코드는 GitHub `gonggong-munseo` main `0f5da7d`에 올라가 있음)

## 1. 한 줄 요약
회사 PC에서 정한 문서편집 결정을 노트북에서 모두 개발해 한글 인쇄본 7개 케이스로 시험했고, 커밋 `0f5da7d`로 GitHub에 올렸다. 회사 PC는 퇴근GO를 다시 켜면 최신판을 받는다.

## 2. 결론·결정 사항
1. (결정) **넘친 줄 6줄 이내면 행간으로 1쪽에 맞춘다(160→150→140→130→120%)**, 줄여도 안 맞으면 되돌린다. — 이유: 처음 3줄로 정했으나, 위원 머리 표가 질의마다 쪽의 약 5%를 써서 사례 a 3→4쪽, b 4→5쪽이 됨. 사용자가 6줄로 올림. 130%까지로는 1줄이 남아 원본 답변자료에서도 드물게 쓰는 120%를 마지막 단계로 추가
2. (결정) **넘친 분량 + 다음 질의가 한 쪽에 들어가면 같은 쪽에 둔다. '질의마다 새 쪽'보다 우선** (사용자 답, 모든 질의 답변자료 대상). 붙인 질의가 쪽에 갈리면 다시 뗀다
3. (결정) ☞ 답변 요지 상자 줄의 낱말 벌어짐(줄 폭 80% 미만)은 먼저 자간을 줄이고, 하한이면 AI가 문장을 줄인다. 본문 ◦ 줄은 아직 대상 아님(폭 계산이 부정확)
4. (결정) □ 줄 최대 2줄, 고른 양식에 줄 수 규칙이 있으면 양식이 우선(작성·양식 채우기 지시문에 넣음)
5. (결정) 위원 머리 표 [번호 │ 위원 │ 국장·과장 연락처]를 질의마다 넣고, 연락처는 `국장 ○○○ (000-0000-0000)` 자리 표시. 번호 칸은 지금 질의 번호
6. (결정) 끝줄 10자 이상·넘치는 구절만 자간 줄이기·자간 하한 -15%를 모든 문서 종류 기본값으로
7. (결정) 출근 버튼은 프로그램 최신판도 받아 다시 켜고(손댄 코드 있으면 받지 않음), 퇴근 버튼은 안 올린 프로그램 커밋도 올린다(커밋 안 한 수정은 알리기만, 다른 PC와 갈라지면 올리지 않음)

## 4. 검토 의견·쟁점
- 한글 'PDF로 저장'은 이 PC에서도 파일을 만들지 않음 → 시험 PDF는 'Microsoft Print to PDF' 인쇄로 만듦
- **AI 줄이기 단계는 시험하지 못함**: 노트북 Claude Code 로그인 만료('OAuth session expired'). 요청문 생성까지만 확인. 명령 프롬프트에서 `claude` 실행해 다시 로그인 필요
- 출근·퇴근은 실제 GitHub·보관함으로 누르지 않고 시험용 저장소 두 개로 흉내 내 5가지 경우 확인
- 원본 머리 표 연락처 칸(54mm·13pt)은 '국장 ○○○ (000-0000-0000)'이 두 줄로 갈려 70mm·12pt·자간 -5로 넓힘
- 정할 것 [확인 필요]: 위원 머리 표 번호 칸에 위원 순번을 따로 둘지(원본은 위원 순번), 본문 ◦ 줄 낱말 벌어짐까지 잡을지

## 6. 새로 정한 작업 규칙
- 질의 답변자료 쪽 맞춤: 넘친 줄 6줄 이내는 행간(최저 120%)으로 1쪽, 그 밖은 넘친 부분 + 다음 질의가 한 쪽에 들면 같은 쪽
- 연락처·전화번호는 AI가 만들지 않고 000-0000-0000 자리 표시로 쓴다
- 편집 방식(끝줄 10자·넘치는 구절 자간)은 모든 문서 종류에 적용한다
